# Testing

The tests exist to prove that the ways this product can fail badly cannot happen. Each starts from a failure vector (what would break the product), names the guard in code, and asserts the guard holds. Test names state the failure they prevent, for example `never schedules a stop outside one open range on its date`. Coverage floors apply too, but only as a backstop: a test earns its place by asserting a guard, not by running code.

On 2026-09-24 `pnpm test` ran about 2,200 tests in about 140 files, in under a minute on a laptop. The E2E and infra suites run on top of that.

## Layers

| Layer | Where | What it covers |
|---|---|---|
| Unit | `packages/planner/test`, `services/api/test/unit`, `apps/web/test` | Pure functions and components. Web tests run in jsdom with Testing Library. |
| Integration | `services/api/test/integration` | The whole Hono app through `app.request()` with a fake clock, fake SSM and the scripted model client; the Lambda handler with API Gateway v2 events. |
| Property | `packages/planner/test/properties`, `planSweep.test.ts`, `validate/mutationProps.test.ts`, `validate/robustness.test.ts`, `normalize/fuzz*.test.ts`, `apps/web/test/shareLink.fuzz.test.ts` | fast-check over arbitrary valid requests, arbitrary stop orders, edits and hostile input. Every property uses the fixed seed 20260923. Planner properties run 500 times by default (the normalizer fuzz 200 to 400, the share-link fuzz 150 to 300); `FC_SEED` and `FC_RUNS` override the planner settings, and `pnpm test:props` sets `FC_RUNS=5000`. A failure prints the seed so it can be replayed. |
| Mutation | `packages/planner/test/validate/mutations.test.ts` with `mutationsTime.ts` and `mutationsPlan.ts` | Valid trips are corrupted one way each (a closed hour, an overlap, a cross-base stop, an invented id, a missing must-include, a wrong day count, a third base, a false travel claim, and more), and the validator must raise the exact code. A test fails if any error code lacks a corruption, so no check can be deleted unnoticed. |
| E2E | `e2e/tests`, `e2e/playwright.config.ts` | The static export served by `e2e/serve.mjs` with the production CSP, directory index and cache headers, `/api` proxied to the local API in fixture mode (no key, no network). Projects: WebKit iPhone SE, iPhone 15 Pro, iPad Pro 11 portrait and landscape, Chromium Pixel 7 and desktop 1280, a Chromium PWA project with the service worker on, and the smoke project. Clock fixed at 2026-10-01 08:00 Europe/Rome; map tiles stubbed; any console error or CSP violation fails the test. |
| Infra | `infra/terraform/*/tests/*.tftest.hcl`, `infra/test` | `terraform test` with mocked providers (plan only, no AWS calls), Vitest checks of the SAM template and scripts, plus tflint, `sam validate --lint`, trivy, actionlint and `check-infra-contract.py` in the `iac` job. |
| Eval replay | `packages/evals` (`pnpm eval:replay`) | Recorded model answers (live runs, or a simulated set until live ones exist, plus hand-written bad answers) replayed through today's pipeline with no network. Only plan validity blocks; model quality numbers are reported in `results/latest.md`, never enforced. |
| Post-deploy smoke | `.github/scripts/smoke-test.sh`, `e2e/tests/site.smoke.spec.ts` | Both hosts report the deployed commit, `/` answers 200, HTTP redirects to HTTPS, security headers are present, the direct execute-api URL and the direct S3 URL answer 403, and optionally a rules-only plan with three valid days. Then a browser loads the site and plans with `?mode=deterministic`, so no tokens are spent. |

Performance has a guard too: `packages/planner/test/performance.test.ts` asserts the median plan and swap-list times stay under 5 times their budgets (50 ms and 100 ms), so a quadratic slip fails without making the test flaky.

## Running them locally

| Command | What runs |
|---|---|
| `pnpm check` | Biome lint, typecheck of every package and `e2e`, then every unit and integration test |
| `pnpm test` | Unit and integration tests for all five Vitest projects (planner, api, web, infra, evals) |
| `pnpm exec vitest run --project planner` | One project (`api`, `web`, `infra` work the same way) |
| `pnpm test:coverage` | The same tests with coverage; fails below the floors |

| `E2E_BASE_URL=https://italy-planner.brdjx.com pnpm test:e2e:smoke` | The browser smoke against the live site |

## Coverage floors

Set per area in `vitest.config.ts`, at the figures measured on 2026-09-24 rounded down, so coverage can only go up. A full `pnpm test:coverage` run enforces them (a single `--project` run reports no coverage).

| Area | Lines | Statements | Branches | Functions |
|---|---|---|---|---|
| `packages/planner/src` | 99 | 98 | 94 | 99 |
| `services/api/src` | 99 | 98 | 92 | 98 |
| `apps/web/lib` | 98 | 96 | 92 | 96 |

Web components are measured but have no floor; their behavior is covered by component and E2E tests. The entry points `services/api/src/local.ts` and `services/api/src/lambda.ts` are excluded: the dev server, the Lambda handler test through `createLambdaHandler`, and the deploy smoke test exercise them. `packages/evals/src` is excluded too: it measures the product rather than being part of it, and its own tests in `packages/evals/test` run in `pnpm test` without a floor.

## Time-zone matrix

The planner runs in browsers in every time zone, and a single `getDay()` instead of `getUTCDay()` would move weekdays for some travelers. The `planner-tz` job in `.github/workflows/ci.yml` runs the planner suite under `UTC`, `Pacific/Kiritimati` (UTC+14) and `America/Los_Angeles` (with DST). `packages/planner/test/guards.test.ts` also fails on any local-time `Date` method in the planner source. The E2E suite pins the browser to Europe/Rome, where the places are.

## What is deliberately not tested, and why

- **The live Claude API in CI.** It costs money and its answers vary, so CI uses the scripted client and a fake Messages API over real HTTP (`integration/anthropicHttp.test.ts`). Live behavior is checked on demand with `pnpm --filter @italy/api live-smoke` (it spends real tokens) and measured by the eval workflow (`.github/workflows/eval.yml`, weekly and on demand, outside CI, so it never gates a merge or a deploy).
- **Real AWS during tests.** `terraform test` uses mocked providers, so it checks what the code asks for, not what AWS accepts. The real account is checked by the plan job on pull requests and by the post-deploy smoke test.
- **Real travel times.** The travel model is straight-line distance in four bands. Tests check the model is applied consistently, not that it matches train timetables.
- **Automated mutation testing of the test suite.** Stryker is not set up. The validator has its own mutation suite (above), which fails if any error code lacks a corruption.
- **Load.** Throttles, reserved concurrency and WAF limits are asserted in the templates and tests, not load-tested.
- **Firefox and physical devices.** Playwright runs Chromium and WebKit with device emulation. Firefox and real phones are outside the automated suite.
- **Pixel-level visuals.** There are no screenshot diffs. Layout is checked by rules (no overflow, 44 px targets, the form folding into the trip summary after planning) and contrast by a CSS token test. During the redesign the E2E job reports without blocking CI (task T62).
