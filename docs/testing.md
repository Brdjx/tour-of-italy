# Testing

The tests exist to prove that the ways this product can fail badly cannot happen. Each starts from a failure vector (what would break the product), names the guard in code, and asserts the guard holds. Test names state the failure they prevent, for example `never schedules a stop outside one open range on its date`. Coverage floors apply too, but only as a backstop: a test earns its place by asserting a guard, not by running code.

On 2026-09-26 `pnpm test` ran 3,500 tests in 212 files. The E2E and infra suites run on top of that. On 2026-09-26 `pnpm test:e2e`, the E2E gate run before a push, ran 372 tests on eight projects in under 5 minutes on a laptop. CI runs its Chromium part (`pnpm test:e2e:ci`: the desktop, the installed app and the smoke tests, 72 tests), which blocks `ci-ok`, so a commit that breaks a user flow on the desktop does not deploy. The WebKit phones and tablets and the Pixel 7 run only locally ([E2E](#e2e-the-local-gate-and-the-ci-guard)).

| Infra | `infra/terraform/*/tests/*.tftest.hcl`, `infra/test` | `terraform test` with mocked providers (plan only, no AWS calls), Vitest checks of the SAM template and scripts, plus tflint, `sam validate --lint`, trivy, actionlint and `check-infra-contract.py` in the `iac` job. |

## E2E: the local gate and the CI guard

`pnpm test:e2e` is the gate for a change to the page: run it before a push. It builds the static export (skip that with `E2E_SKIP_BUILD=1` when only tests changed), starts the API with the scripted model on `127.0.0.1:18790` and the site on `127.0.0.1:14390` (`E2E_API_PORT` and `E2E_WEB_PORT` move them), runs every project with half the machine's cores as workers, and stops both servers at the end. On 2026-09-26 it took 4.7 to 5.0 minutes on an 8-core laptop with 8 GB of memory, with no failure in five full runs. Keep the default workers: with 12 the same laptop was overloaded (load averages up to 114 on 8 cores, swap in use), the suite took 8.2 to 9.1 minutes in three runs, and one of them failed on a wait that counted the test's own time (fixed since in `planTrip`). A busy port fails the run at once; `E2E_REUSE=1` tests against servers already running there instead. A failure leaves a report in `e2e/playwright-report` (`pnpm exec playwright show-report e2e/playwright-report`) with a screenshot and, in CI, a trace of the retry.

The CI `e2e` job runs `pnpm test:e2e:ci`, the Chromium guard: `chromium-desktop` (every device spec and the keyboard spec), `pwa-chromium` (the service worker) and `smoke`, with only Chromium installed. On the 4-core runner the full suite took 23 to 34 minutes, WebKit ran 4 to 8 times slower than on a laptop, and route tests reached the 60 s limit on the iPads (runs 36251394496, 36265600500 and 36249317699, 26 September 2026). In the slowest of those runs the guard's projects took 14.4 minutes of test time, about 3.6 minutes on 4 workers. So the WebKit phones and tablets and the Chromium Pixel 7 run only on the laptop, and a change that breaks them alone is caught by `pnpm test:e2e`, not by CI. The job has 15 minutes, and Playwright stops the guard after 10 (`--global-timeout` in the script), so a run that hangs fails with its report uploaded before the job's limit can cancel it.

Tests wait on state, never on a fixed time: a locator assertion, `expect.poll`, a held route or the API's own answer. Where the page waits on a timer, the test moves Playwright's clock (`page.clock.runFor`). Each test has 60 s; the long audit test takes three times that (`test.slow()`).

## Coverage floors

Set per area in `vitest.config.ts`, at the figures measured on 2026-09-24 rounded down, so coverage can only go up. A full `pnpm test:coverage` run enforces them (a single `--project` run reports no coverage).

| Area | Lines | Statements | Branches | Functions |
|---|---|---|---|---|
| `packages/planner/src` | 99 | 98 | 94 | 99 |
| `services/api/src` | 99 | 98 | 92 | 98 |
| `apps/web/lib` | 98 | 96 | 92 | 96 |

Web components are measured but have no floor; their behavior is covered by component and E2E tests. The entry points `services/api/src/local.ts` and `services/api/src/lambda.ts` are excluded: the dev server, the Lambda handler test through `createLambdaHandler`, and the deploy smoke test exercise them. `packages/evals/src` is excluded too: it measures the product rather than being part of it, and its own tests in `packages/evals/test` run in `pnpm test` without a floor.

## Time-zone matrix

The planner runs in browsers in every time zone, and a single `getDay()` instead of `getUTCDay()` would move weekdays for some travelers. The `planner-tz` job in `.github/workflows/ci.yml` runs the planner suite under `UTC`, `Pacific/Kiritimati` (UTC+14) and `America/Los_Angeles` (with DST). `packages/planner/test/guards.test.ts` also fails on any local-time `Date` method in the planner source. The E2E suite pins the browser to Europe/Rome, where the places are.

## What is deliberately not tested, and why

- **The live Claude API in CI.** It costs money and its answers vary, so CI uses the scripted client and a fake Messages API over real HTTP (`integration/anthropicHttp.test.ts`). Live behavior is checked on demand with `pnpm --filter @italy/api live-smoke` (it spends real tokens) and measured by the eval workflow (`.github/workflows/eval.yml`, started by hand only, outside CI, so it never gates a merge or a deploy).
- **Real AWS during tests.** `terraform test` uses mocked providers, so it checks what the code asks for, not what AWS accepts. The real account is checked by the plan job on pull requests and by the post-deploy smoke test.
- **Real travel times.** The travel model is straight-line distance in four bands. Tests check the model is applied consistently, not that it matches train timetables.
- **Automated mutation testing of the test suite.** Stryker is not set up. The validator has its own mutation suite (above), which fails if any error code lacks a corruption.
- **Load.** Throttles, reserved concurrency and WAF limits are asserted in the templates and tests, not load-tested.
- **Firefox and physical devices.** Playwright runs Chromium and WebKit with device emulation. Firefox and real phones are outside the automated suite.
- **Pixel-level visuals.** There are no screenshot diffs. Layout is checked by rules (no overflow, 44 px targets, the form in the Edit trip sheet once there is a plan, the map beside or under the board) and contrast by a CSS token test.
